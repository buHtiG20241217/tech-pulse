# User Guide

## 1. Requirements

- Windows, macOS or Linux with Python 3.10 or newer (tested on Python 3.13 and 3.14, Windows 11).
- About 1 GB of disk for the dependencies (PyTorch is pulled in by sentence-transformers).
- Internet on first start, to download the embedding model (about 90 MB, cached afterwards).
- Optional: a Mistral API key (console.mistral.ai) or Azure OpenAI credentials. Without one,
  extraction, search, checks, comparison and review all work; only written answers need the model.

## 2. Install

```powershell
cd Code\autosar_hld_assistant
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## 3. Configure the language model

Any of the following works; values set in the shell take precedence over `.env`.

- **`.env` file:** copy `.env.example` to `.env` and set `MISTRAL_API_KEY`.
- **Shell:** `$env:MISTRAL_API_KEY = "<key>"` before starting.
- **In the app:** sidebar → *Model settings* → choose a provider, paste the key, then *Apply*. This
  applies to your browser session only and is not saved.

Azure OpenAI needs `LLM_PROVIDER=azure`, `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY` and
`AZURE_OPENAI_DEPLOYMENT`. All settings are listed in `../Model_Prompts_Config/126003133_ModelConfiguration_v1.0.md`.

## 4. Start

```powershell
.\launch.ps1                         # or: python -m streamlit run app/main.py
```

Open http://localhost:8501. The REST API is optional and runs separately, from the folder that
contains `autosar_hld_assistant`:

```powershell
cd ..
python -m uvicorn autosar_hld_assistant.app.api:app --port 8000   # docs at http://localhost:8000/docs
```

## 5. Pages

The pages are listed across the top. The sidebar shows the model status, model settings, the size
of the knowledge base and a *Reset* panel.

### Documents
- **Upload** one or more PDFs, then press *Index uploaded files*, or press *Index* next to a sample.
- *Refine extraction with the language model* is on by default when a model is configured. It lets
  the LLM fill gaps the table
  parsers left. Anything it adds is labelled `llm`.
- A progress panel shows each stage. Indexing a document that is already indexed replaces it.
- *Knowledge base* shows totals and one row per document. *Remove a document* deletes its passages
  and elements; review history is kept.

### Ask
- Type a question, or click a suggestion.
- Each answer shows a status line: *Answered: from N passages, evidence match: high / medium / low*,
  or *Not answered* with the reason.
- *Sources* lists every passage used: document, page, section, distance, and the text itself.
- Follow-up questions work: a question that refers back ("which interfaces do they use?") and
  finds no evidence on its own is retried together with the previous question. Unrelated questions
  are never combined.
- *New conversation* clears the chat.

### Architecture
- Pick one document or all of them. The metrics show element counts.
- **Dependency graph**: SW-Cs with their dependencies, labelled by interface.
- **Checks**: potential inconsistencies, ranked Error, Warning, Info. Each needs confirming
  against the document.
- One tab per element type, showing review status and how each element was found (`table`,
  `regex` or `llm`).

### Compare
Pick an older and a newer revision. You get a summary table, then the elements added, removed and
changed. Try it with the two EBC samples (rev 1.2 → rev 1.3).

### Review
1. Choose an element type. The progress bar shows how many are reviewed.
2. Pick an element. *Pending only* hides the ones already reviewed.
3. Choose *Approved*, *Rejected* or *Edited*. *Edited* shows the editable fields.
4. Enter your name and a rationale (both required), plus safety or risk notes if relevant.
5. Press *Record decision*. The review log below shows every decision, newest first, with old and
   new values for edits.

### Export
Download a Markdown report (summary with review counts, all element tables, consistency findings,
review log), a JSON export, or the CSV tables as a zip. A preview of the report is shown below the
buttons.

## 6. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Sidebar shows *Not configured* | No key | Set `MISTRAL_API_KEY` or use *Model settings* |
| *The language model request failed: … 401* | Wrong or revoked key | Check the key |
| *… 403* with `mistral-large-latest` | Needs a paid plan | Use `ministral-8b-latest` (the default) |
| Error about loading the embedding model on start | No network on first run | Connect once; set `HF_TOKEN` if rate-limited |
| *No text found … Scanned PDFs need OCR first* | Image-only PDF | Run OCR on the PDF first |
| *Vector index has N vectors but metadata has M* | Index files out of step (e.g. copied separately) | Delete `data/faiss_index.bin` and `data/faiss_metadata.json`, then re-index |
| A reasonable question is refused | Distance just above the threshold | Name the element (SW-C, port, interface); or raise `SIMILARITY_THRESHOLD` |
| `launch.ps1` blocked | PowerShell execution policy | `powershell -ExecutionPolicy Bypass -File .\launch.ps1` |
