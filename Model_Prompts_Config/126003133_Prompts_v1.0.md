# Prompts

Every prompt the application sends to a language model, copied from the source. If the source and
this file ever disagree, the source is authoritative.

## 1. Grounded question answering

Source: `Code/autosar_hld_assistant/app/rag/qa_engine.py` (`SYSTEM_PROMPT`). Sent only when the
best retrieved passage has a distance ≤ 1.1.

### System prompt

```text
You answer questions about AUTOSAR High-Level Design (HLD) documents for automotive software engineers.

Rules:
1. Use only the information in the numbered passages under CONTEXT. Do not add facts from general knowledge.
2. Cite the passage behind each statement as [Doc: <name>, Page: <number>, Section: <section>].
3. Use earlier turns of the conversation only to work out what the question refers to.
4. Be concise. Prefer lists and tables when listing components, ports or signals.
5. If the passages do not contain the answer, reply with exactly this sentence and nothing else:
The provided AUTOSAR HLD documents do not contain sufficient evidence to answer this question.
```

### Message sequence

```text
system     <system prompt>
user       <earlier question>        ┐ up to the last 6 turns,
assistant  <earlier answer>          ┘ user/assistant only
user       QUESTION: <question>

           CONTEXT:
           [1] Doc: <document>, Page: <n>, Section: <section>
           <passage text>

           ---

           [2] …                     (top 5 passages)
```

Settings: `temperature = 0.0`, `max_tokens = 1500`.

### Design rationale

| Element | Purpose |
|---|---|
| Role line naming the audience | Sets the domain vocabulary (SW-C, ports, sender-receiver) |
| Numbered rules | Smaller models follow explicit, enumerated constraints more reliably |
| "Do not add facts from general knowledge" | Blocks answers from training data |
| Literal citation format | Gives checkable `[Doc, Page, Section]` tags |
| Rule 3 on conversation history | History resolves references ("it", "those ports") but is not a source of facts |
| Exact refusal sentence | The code detects it with a substring test and reports *not answered* |
| Temperature 0 | Deterministic, factual output |

## 2. Entity extraction refinement

Source: `Code/autosar_hld_assistant/app/extraction/autosar_extractor.py` (`LLM_SYSTEM_PROMPT`).
Used when indexing with *Refine extraction with the language model* on, which is the default when a
model is configured.

### System prompt

```text
You extract software architecture elements from AUTOSAR High-Level Design documents.

Return a JSON object with exactly these keys, each holding a list of objects:
- "swcs": {"name", "type", "description"}
- "interfaces": {"name", "type" ("Sender-Receiver" or "Client-Server"), "description"}
- "ports": {"name", "direction" ("Provided" or "Required"), "swc_owner", "interface_ref"}
- "signals": {"name", "data_type", "unit", "interface_ref"}
- "dependencies": {"source_swc", "target_swc", "interface_name"}
- "functional_flows": {"flow_name", "sequence", "description"}

Copy names exactly as written in the text. Include only elements that appear in the text.
List each element once. Keep every description under 12 words.
A functional flow "sequence" is a chain of component names such as "A -> B -> C".
Do not list AUTOSAR Basic Software modules such as CanIf, PduR, Com, NvM, Dem or Rte.

Reply with a single JSON object and nothing else.
```

The last line is appended by `LLMClient.chat_json`.

### User prompt

```text
Document: <file name>

<up to 12,000 characters: the pages with the most architecture names, in page order>
```

Settings: `temperature = 0.0`, `max_tokens = 6000`, provider JSON mode (`response_format = json_object`).

### Post-processing

1. ```` ``` ```` fences are stripped and the reply is parsed as JSON. A reply cut off by the token limit
   keeps its complete items; anything unusable is discarded with a logged warning.
1b. Items are cleaned: only the fields above are kept, names must be identifiers (not sentences),
   and a flow's sequence must be a component chain.
2. Items are merged into the table results by key, filling only missing or placeholder fields. New
   items are added, labelled `source = "llm"`, only for element kinds the document has no table for.
3. Basic Software module names and port-like signal names are removed, including from LLM output.

## 3. Without a language model

No prompt is sent. The Ask page shows *"No language model is configured. The most relevant
passages are listed below."* together with the retrieved passages.
